Audio engine

One duplex stream, one callback

The tuner, metronome, looper and recorder tap the amp's stream instead of opening their own, so nothing competes for the device.

ParameterValue
Sample rate44,100 Hz, fixed. Devices configured at another rate are opened through WASAPI's automatic rate/channel conversion; the DSP always runs at 44.1 kHz.
Stream formatfloat32, 1 input channel (the guitar) in, 2 channels out (the mono signal on both).
Internal precisionfloat32 signal path. NAM inference runs in float64 and is returned as float32; the EQ's filter state and the cab-IR FFT are float64.
Block size256, 512, 1024 or 2048 samples = 5.80 / 11.61 / 23.22 / 46.44 ms per block. 256 is the smallest size that holds up with a NAM model and a cab IR loaded.
Host APIsWASAPI (default), WDM-KS, DirectSound and MME on Windows; Core Audio on macOS; ALSA on Linux, via PortAudio. No ASIO.
Latency, DSPNo look-ahead anywhere in the chain: NAM runs as a causal streaming model, cab convolution is overlap-add (each block is returned as it arrives), and the dynamics have no look-ahead buffer. The 4× oversampled clip stages add only the group delay of their anti-alias filters.
Latency, round tripInput buffer + one processing block + output buffer + driver/converter latency. Plan on at least two block lengths (11.6 ms at 256). The status line shows the figure the audio API reports once the stream is running.
Process priorityRaised to HIGH on Windows while the amp is running.
Processing time

What the chain costs per block

The callback must finish each block in less time than the block lasts. These figures are the load a real chain puts on that budget.

Full chains, by block size

Medians across 31 real Tone Profiles (standard WaveNet NAM models, cab IRs from none to 1 s, pedals as saved), each processing 12 s of plucked-string audio block by block. “Range” is the lightest to heaviest profile; “p99 block” is the 99th-percentile single block; “Worst block” is the slowest single block as a multiple of the budget. Offline harness: no audio device, normal process priority, a desktop session running alongside.

Reading it: at 256 samples this CPU averages about half the budget, but isolated blocks can overrun, which is an audible click. 512 samples is the comfortable setting; 1024 is for slower machines. Cost scales roughly inversely with single-thread speed, so a CPU with half this one's would need 1024 or more (estimate, not measured).

Off the audio thread

OperationCost
RecordingThe callback only copies each block into a bounded queue (4,000 blocks, about 23 s at 256); a writer thread does the disk work. Dropped blocks are counted and reported, never silently lost.
Re-ampAbout 1.4× real time through the heaviest chain tested (standard NAM, 1 s cab IR, pedals), on a worker thread with a cancel button. Normal chains are faster.
Match levelA few seconds per sound: it renders a 6.3 s synthetic playing signal through the whole chain offline.
Tuner analysis0.81 ms per reading (12,288-sample window), about 11 readings per second, on the interface thread.

Test machine: AMD Ryzen 7 5800X (8 cores / 16 threads, 3.8 GHz base), 32 GB RAM, Windows 11, Python 3.10, NumPy 2.2.6, SciPy 1.15.3. The NAM engine is pure NumPy; there is no compiled NAM core and no GPU use.

Formats & bit depths

What goes in, what comes out

ItemFormat
Recording (wet & dry)WAV, mono, IEEE float 32-bit, 44.1 kHz. Sample-aligned pair; the header is rewritten every second, so a take cut short still opens. Tapped after Output Gain, before Master Volume and the metronome click.
Re-amp inputWAV, 8/16/24/32-bit integer PCM or 32/64-bit float, any sample rate; multichannel files are averaged to mono.
Re-amp outputWAV, mono, 32-bit float, at the source's sample rate (polyphase resampling with SciPy), plus a 2 s tail for reverb and delay.
Looper exportWAV, mono, 16-bit PCM, 44.1 kHz — a single layer or the whole mix.
Cab IRsWAV: 8/16/24/32-bit PCM, 32/64-bit float, including WAVE_FORMAT_EXTENSIBLE headers (parsed directly, not through Python's wave module). Resampled to 44.1 kHz and L1-normalized on load. Five slots, A/B and blend.
Amp modelsNeural Amp Modeler .nam, WaveNet architecture (A1 and A2 exports, SlimmableContainer files use the highest-quality submodel). LSTM captures are not supported.
Tone Profiles.stprofile: JSON with a format-version field. Amp and IR paths, every pedal parameter and the chain order, pedal MIDI mappings, EQ, gate, gains, hum filter, tuning, notes.
Pedal presets.stpedal: JSON, one pedal's parameters, portable between profiles.
DSP details

How each block is built

Signal order: hum filter, pre-amp pedals, input gain, noise gate, NAM, cab IR, EQ, post-amp pedals, Output Gain, Master Volume.

BlockImplementation
Noise gateStandard: block-RMS detector against a threshold; 3 ms attack and 60 ms release time constants, applied as a per-sample linear ramp across each block so block edges don't click. Smart: level read from an 8 ms power average in 64-sample steps, opens at the threshold and closes 6 dB below it, with hold, adjustable depth and release, and a Hush expander that fades a dying note into the noise. Block-size independent.
Hum filterCascaded IIR notches (Q = 25) at the mains frequency (50 or 60 Hz) and its next two harmonics.
Cab IROverlap-add FFT convolution, FFT length rounded up to the nearest 5-smooth size; the IR spectrum is cached per block size.
EQFive biquads: low shelf 100 Hz (Q 0.707), peaking 400 Hz, 1 kHz and 2.5 kHz (Q 1.0), high shelf 6 kHz (Q 0.707); ±15 dB each, plus a ±15 dB level trim.
CompressorSoft-knee gain computer (6 dB knee), one-pole envelope follower, blendable tube-style saturation.
Fuzz & distortionClip stages run 4× oversampled to suppress aliasing, with a DC blocker; Fuzz Face / Tone Bender / Big Muff and DS-1 / RAT / Distortion+ / Metal voicings.
WahState-variable filter; manual position, auto-sweep, or envelope mode (level-following wah / band / low-pass / high-pass, up or down).
Chorus / flanger / vibrato / doubler, delayLFO-modulated delay line (vibrato is fully wet, the doubler a short delay with a slow drift); delay is tape (low-passed feedback) or digital, free-running or tempo-synced.
Phaser, tremoloPhaser: four first-order all-passes swept by a per-sample sine LFO, with feedback, 50/50 with the dry signal. Tremolo: amplitude modulation from a sine blended toward a square-ish wave.
ReverbRoom: Schroeder topology, four parallel comb filters into series all-passes. Plate and Cloud: a Dattorro-style network (input diffusers into two cross-coupled damped tanks). Spring: three parallel springs, each a delay loop with a 24-section all-pass dispersion chain. Plate, Cloud and Spring run as vector operations and give identical output at any block size.
Pedal chainTen effects around an AMP marker. Pre-amp pedals run ahead of the model; post-amp pedals run on the amp, cab and EQ output.
Looper1–60 s loops, up to 10 layers, sample-count locked so layers cannot drift. Records the processed output; float32 buffers, 10.6 MB per layer at the longest length.
MetronomeScheduled inside the audio callback, so clicks are sample-accurate regardless of CPU load; 30–250 BPM.
TunerMcLeod normalized square-difference pitch detection with parabolic interpolation, on a 12,288-sample window (278 ms; 16,384 in Bass mode). Loudness-independent; mains hum is subtracted by least squares before detection. Chromatic range about 40–1500 Hz (24–600 Hz in Bass mode); with a tuning selected the search narrows to that tuning's strings. On synthetic plucked-string signals (six strings, ±25 cents, −26 and −50 dBFS) the mean error was 0.07 cent and the worst 0.5 cent.
MIDI & keys46 MIDI-mappable controls and 67 keyboard-mappable targets, learned by touching the control; Akai LPD8 mk2 pad LED feedback.
What's different

Unique features

NAM in pure NumPy

A from-scratch WaveNet inference engine with streaming state: no PyTorch, no compiled NAM core, no GPU. It installs with pip and runs the same on Windows, macOS and Linux.

Pre- and post-amp chain

An AMP marker splits the pedal order: drive and dynamics ahead of the model, time-based effects after it, so repeats and tails aren't compressed by a distorted amp.

Wet + dry recording

Two sample-aligned float WAVs per take, tapped before Master Volume and the click, written from a separate thread so the audio callback never touches the disk.

Offline re-amp

Run any WAV through the current sound at faster than real time. The offline chain is a GUI-free mirror of the live callback, so a render is what you would have heard.

Loudness matching

Match level measures a synthetic playing signal through the whole chain and sets Output Gain so every profile sits at −18 dBFS RMS, closing gaps of 40 dB between amp captures.

Tuning-aware tuner

With a tuning selected, readings snap to that tuning's strings (octave-insensitive, with hysteresis); hum-subtracted detection finds quiet single-coil pickups.

One shared stream

The tuner, metronome, looper and recorder read from the amp's callback. There is no second stream to fight over the interface.

Whole-rig profiles

A profile is plain JSON: model, IRs, every pedal parameter and order, EQ, gains, tuning, MIDI mappings for the pedals, and your notes on pickup and knob settings.

Local, source-available

No network access, account or telemetry. Source-available under the PolyForm Shield License 1.0.0; it is not an OSI open-source license.

Requirements & current limits

What it needs, and what it doesn't do

ItemDetail
PlatformsWindows: standalone .exe, no Python needed. macOS and Linux: from source on Python 3.10 or later.
DependenciesNumPy 1.24+, sounddevice 0.4.6+. Optional: SciPy 1.11+ (EQ filter stability, resampling), python-rtmidi (MIDI), Pillow (button corners, pedal icons).
Audio deviceAny interface or microphone input the OS exposes; mono input. No ASIO driver is used or needed.
Fixed 44.1 kHzNAM captures are run at the app's 44.1 kHz rate. They are not resampled to the rate they were trained at, which is usually 48 kHz.
ModelsWaveNet NAM only; LSTM captures don't load.
Block size floor256 samples. Smaller sizes don't keep up with a model and a cab IR in the Python callback.
